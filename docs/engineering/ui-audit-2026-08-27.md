# UI Audit: `feat/design-system-theme`

日期：2026-08-27  
分支：`feat/design-system-theme`  
檢查基準：本機 `204e3b5` 加上當時未提交的 `TimetablePage.tsx` 與 `variables.css` 修改

## 1. Scope

本次只審查此 UI 分支應負責的項目：

- 響應式版面與資訊可讀性
- 導覽、控制項狀態與操作回饋
- 觸控尺寸、語意與基本可及性
- Design System 完整性與頁面間一致性
- 瀏覽器執行時的 UI 警告

以下項目不作為本 UI 分支的合併阻擋條件：Firebase、Authentication、Firestore、圖片上傳、正式 QR 掃描、後臺、Flag server、正式抽籤資料與其他後端流程尚未實作。

但是，尚未實作的功能不得呈現成可正常操作的控制項。UI 應明確使用停用、`Coming soon`、Demo 或假資料標示。

## 2. Test matrix

檢查路由：

- `/`
- `/guide`
- `/cards`
- `/leaderboard`
- `/seats`
- `/stage/lottery`
- `/timetable`

九個路由都可載入，未發現整頁水平 overflow。首頁模組連結、底部 Tab、排行榜連結及研究室分頁可正常切換。

## 3. Must fix before calling the UI complete

### UI-01 — Mobile timetable is not readable

Severity: High  
Route: `/timetable`

- 320px 與 390px 下使用 8–10px 課程、教師、教室與時間文字。
- 多個課名被 ellipsis 截斷，使用者無法辨識完整課程。
- 一次塞入五個平日欄位雖避免水平 overflow，卻以犧牲可讀性達成。

最低修正：手機改成每日切換、單日清單或可水平滑動且保留正常字級的週表。不得再縮小至 12px 以下來硬塞五欄。

### UI-02 — Lottery stage is still a phone layout

Severity: High  
Route: `/stage/lottery`

- 1440px 桌面只顯示約 608px 寬的置中卡片。
- 投影模式仍保留手機用返回鍵與底部 Tab Bar。
- 沒有 16:9 舞台資訊層級、全螢幕控制、進度或結果區域。

最低修正：讓舞台路由脫離一般 `IonTabs` shell，建立單一真正的寬螢幕 layout；抽籤邏輯可繼續使用假資料。

### UI-03 — Controls falsely imply completed behavior

Severity: High

- `/cards` 的「掃描 Entry Code 報到」為啟用狀態，但點擊後 URL、內容與狀態完全不變。
- `/tools/credit` 的 checkbox 可點擊，但必修、選修與總學分永遠維持 0。
- `/guide` 前六個「校園資源直達車」連結使用 `href="#"`。
- 指南檢核清單全部呈現完成圖示，但沒有互動或資料來源。
- Leaderboard 使用 mock data，畫面沒有 Demo 或假資料標示。

最低修正：UI 分支不必實作後端，但必須讓 Demo 互動在前端成立，或明確停用並標示尚未開放。

### UI-04 — Primary touch targets are too short

Severity: Medium  
Routes: `/cards`, `/stage/lottery`, `/food`

主要 `IonButton` 實測高度約 36–39px，低於專案規格要求的 44px 觸控目標。

最低修正：由共用 theme 統一主要按鈕最小高度，不逐頁覆寫。

### UI-05 — Timetable produces a React key warning

Severity: Medium  
Route: `/timetable`

瀏覽器 Console 顯示：`Each child in a list should have a unique key prop`。來源是 `TimetablePage` 的資料列 fragment。

最低修正：在 map 的最外層 fragment 加入穩定 key。UI PR 不應留下 runtime warning。

### UI-06 — Design System theme is incomplete

Severity: Medium

- `Noto Sans TC` 只出現在 font-family fallback，repository 沒有自帶字型或 `@font-face`。
- Ionic `success`、`danger` 只設定 base 與 RGB，缺少 contrast、shade、tint token。
- 可見 Header 使用 `NCUIM 2026 Fresher`，瀏覽器 title 使用 `NCUIM 2026 Fresher Mixer`。

這三項也對應目前 PR #4 尚未處理的 Sourcery review findings。

## 4. Follow-up UI improvements

### UI-07 — Desktop content frame is visually awkward

- 多數頁面固定為約 608px 寬，1440px 桌面留下大量空白。
- `/guide` 的捲軸貼在中央內容欄右側，像嵌入式小視窗。
- 一般內容頁可維持手機優先窄欄，但桌面需有一致的 page frame；舞台與課表必須使用自己的寬版 layout。

### UI-08 — Navigation labels and localization need cleanup

- Tab「使用者」語意過廣，建議改為「我的卡片」或「卡片」。
- 返回鍵的 accessible name 是英文 `back`，與繁體中文畫面不一致。
- 尚無 `en`／`zh-TW` 切換與翻譯資源。

### UI-09 — Pixel identity is not yet visible enough

- 現況主要是 Ionic 卡片加粗框線，尚未形成完整的 Pixel Quest 視覺語言。
- Query Cat、活動字標、像素 display font 與 repository-owned icon set 尚未出現。
- Leaderboard 使用一般 emoji，與預定像素圖示不一致。

如果本分支只宣稱建立基礎 theme，這項可拆到下一個 UI asset PR；如果宣稱完成視覺設計，則必須在本分支補齊。

## 5. Recommended merge boundary

此 UI 分支完成的最低界線：

1. 修正 UI-01 至 UI-06。
2. 保留 Firebase 與正式業務流程為後續工作。
3. 用本機假資料完成可操作的畫面狀態，不增加新的服務或狀態管理套件。
4. 在 320px、390px 與 1440px 重跑所有路由，Console 不得有 error/warning。
5. 補最少量的 UI smoke tests，至少覆蓋導覽、學分勾選及研究室分頁。

## 6. Evidence summary

- 所有路由均能載入。
- 320px、390px、1440px 未發現整頁水平 overflow。
- `/cards` 報到按鈕點擊後沒有任何狀態變化。
- `/tools/credit` checkbox 點擊後統計沒有變化。
- `/guide` 有六個 `#` placeholder links。
- `/timetable` 有 React list key warning。
- 手機課表字級最低 8px。
- 卡片、抽籤與美食主要按鈕高度低於 44px。

本紀錄只保存診斷結果，不代表已完成修正。
